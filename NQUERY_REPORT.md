# jmesh nquery — Phase 1 Bring-Up Report

**Date:** 2026-07-26 · **Scope:** natural-language → SQL via local ONNX model · **Status:** ✅ working end-to-end

---

## TL;DR

The `nquery` feature (ask questions in English, get SQL generated by a local
T5 model, executed against your SQLite DB) went from **15 compile errors
(plus more queued in the CLI target) and an unwired runtime** to a working
pipeline:

```console
$ jmesh nquery "what are the names of users whose age is greater than 26?" demo.db
[
  { "name": "Alice" },
  { "name": "Carol" },
  { "name": "Dan"   }
]                                    # ~7 s per query, release build
```

```console
$ jmesh nquery "how many users are in each city?" demo.db --explain
-- Generated SQL:
SELECT city, COUNT(*) FROM users GROUP BY city
```

All **24 tests pass** (5 unit · 16 integration · 3 doc), including a new
`sanitize` test suite.

## What was broken → what we did

### 1. `SchemaCache` regression (6 compile errors)
A refactor had dropped `Debug`, `table_exists()`, and `column_names()` while
`db.rs`, `table.rs`, and `fts.rs` still used them.
**Fix:** restored all three (`src/schema.rs:27`, `:73`, `:80`).

### 2. tract API misuse in the ONNX engine (9 compile errors)
`Tensor::from(ndarray)` across an ndarray version mismatch, missing `TValue`
conversions in `tvec!`.
**Fix:** engine rewritten on `Tensor::from_shape` + name-based input wiring;
dropped the direct `ndarray` dependency (`src/nquery/engine.rs`).

### 3. CLI handler referenced nonexistent API
`database.prepare()`, `jmesh::types::sqlite_to_json`, `JmeshResult` — none exist.
**Fix:** handler now reuses `Database::query()` (`src/bin/cli.rs:239`).

### 4. `--allow-write` was dead code (security logic)
- `sanitize::check` enforced SELECT/WITH **unconditionally** → write mode could
  never pass.
- `ask()` always sanitized read-only before the CLI flag was consulted.
- Substring matching (`contains("DELETE ")`) was both naive and bypassable.

**Fix:** `allow_write` flows from CLI → `ask()` → `sanitize`; word-boundary
matching (a `created_at` column no longer trips `CREATE`); `DROP` forbidden in
all modes; new `Error::UnsafeSql` variant replacing the misleading
`InvalidPrimaryKey` label. 5 unit tests added (`src/nquery/sanitize.rs`).

### 5. tract couldn't load the model (two distinct bugs)
- **0.21:** `Range` node → `encoder_sequence_length TDim vs I64` mismatch →
  **upgraded tract-onnx to 0.23.4**.
- **0.23:** `ChangeAxes` optimizer pass panics on the quantized decoder's
  `Unsqueeze` nodes → loader now tries optimized, falls back to typed graph
  (`engine.rs:151`).

### 6. Decoder inputs wired by position — wrong order
This ONNX export declares `encoder_hidden_states` **before** `input_ids`;
positional wiring fed tensors to the wrong inputs.
**Fix:** `named_inputs()` matches tensors by graph input name (`engine.rs:166`).

### 7. Model files unusable
Disk had: no `tokenizer.json` (only `spiece.model`, which the `tokenizers`
crate can't read), a **merged** fp16 decoder (needs past-KV plumbing), and code
expecting `*_q4.onnx` names that don't exist in the repo.
**Fix:** downloaded `tokenizer.json` + non-merged quantized pair; engine
auto-discovers q4 → quantized → fp16 → plain; `script/download-nquery-model.py`
rewritten to fetch exactly what's needed; `.gitignore` excludes `*.onnx`
(~450 MB) and the HF cache.

### 8. Off-manifold prompt
Code used `query:`, but the model was fine-tuned on
`tables:\n<CREATE TABLEs>\nquery for: <question>` (single-line CREATEs) — see
the [model card](https://huggingface.co/cssupport/t5-small-awesome-text-to-sql).
**Fix:** prompt + schema rendering matched to the training format
(`src/nquery/mod.rs:27`).

### 9. Smaller items
- `kstring@2.0.3` requires rustc 1.96 → pinned to 2.0.2 (toolchain is 1.95).
- `learn` looked in `scripts/` (repo has `script/`); now checks both, with a
  clear "phase-2 trainer not shipped yet" error, and validates the script
  before creating the output dir.
- 3 pre-existing `unused mut` warnings cleaned up.
- CHANGELOG updated (Unreleased section).

## Pipeline as built

```
 question ──┐
            ▼
 schema introspection (sqlite_master + PRAGMA table_info, cached)
            ▼
 prompt:  "tables:\nCREATE TABLE users (id INTEGER, ...);\nquery for: …"
            ▼
 tokenizers (tokenizer.json) ──► T5 encoder (ONNX, tract)
            ▼
 greedy decode loop (≤128 tokens, EOS stop, inputs wired by name)
            ▼
 sanitize: DROP forbidden · read-only = SELECT/WITH · --allow-write opt-in
            ▼
 rusqlite execute ──► JSON rows on stdout
```

## Known limitations (honest list)

- **Model quality is t5-small.** Question-style phrasing works well;
  command-style ("list all users…") can hallucinate columns (`SELECT user FROM
  users`). Errors surface cleanly — nothing silent.
- **No KV caching.** The plain decoder recomputes the full sequence each token
  (~7 s/query). The `decoder_model_merged_*` variants with past-key-values
  would cut this substantially but need the past-KV plumbing.
- **`jmesh learn` has no trainer yet.** The command is wired, but
  `script/tinygrad_trainer.py` does not exist — that's the phase-2 work.

## Phase 2 roadmap (self-training to shrink the model)

1. Write `script/tinygrad_trainer.py`: generate (question, SQL) pairs from the
   live schema, fine-tune / distill into a smaller student.
2. Export the student to ONNX → drop into `models/nquery` (engine
   auto-discovers `*_q4.onnx` first).
3. Optional: past-KV decoding for ~5–10× faster generation.
